# SkillRL Baseline for Tau-Bench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement SkillRL (Recursive Skill-Augmented RL) as a baseline on tau-bench, adapting the paper's approach to our existing GRPO infrastructure with Qwen3-30B-A3B.

**Architecture:** SkillRL injects a hierarchical SkillBank into the agent's system prompt during both SFT and GRPO training. Skills are structured JSON entries distilled from trajectory analysis. During GRPO, a recursive evolution loop analyzes validation failures and generates new skills using the base model via vLLM. The pipeline has 3 stages: (1) SkillBank generation, (2) Cold-start SFT, (3) GRPO with skill evolution. We adapt our existing `train_grpo_optimized.py` and `train_sft_adp.py` rather than porting SkillRL's verl framework.

**Tech Stack:** Python, PyTorch, unsloth (4-bit QLoRA), vLLM (rollout + skill evolution), existing GRPO trainer, tau2-bench evaluation harness.

## Task 5: Implement Recursive Skill Evolution

**Files:**
- Create: `skillrl/skill_evolution.py`

- [ ] **Step 1: Implement skill evolution module**

`skill_evolution.py` contains:
- `evolve_skills()` — main function called after validation
  - Takes: failed trajectories, current SkillBank, vLLM backend URL, model name
  - Analyzes failures against existing skills
  - Generates 1-3 new skills per evolution step
  - Returns updated SkillBank
- `analyze_failures()` — groups failures by category, selects worst-performing categories
- `generate_new_skills()` — calls vLLM-served model with evolution prompt

Integration: Called in the GRPO training loop after tau2-bench evaluation, when domain accuracy < threshold (default 0.4).

## Task 6: Create SkillRL GRPO Training Script

**Files:**
- Create: `train_skillrl_grpo.py`

- [ ] **Step 1: Create GRPO wrapper with skill injection and evolution**

`train_skillrl_grpo.py` wraps `train_grpo_optimized.py` with:
- SkillBank loading at startup
- Skill injection into game environment via `--game adversarial_policy_skillrl`
- Recursive evolution loop after each tau2-bench evaluation:
  1. Run tau2-bench eval
  2. If domain_accuracy < threshold, collect failed trajectories
  3. Call `evolve_skills()` with failures + current SkillBank
  4. Update SkillBank JSON file
  5. Refresh game environment with new skills

This is a thin wrapper — all GRPO logic stays in `train_grpo_optimized.py`.

- [ ] **Step 2: Add CLI arguments**

```
--skill-bank-dir         Path to skill JSON files (default: skillrl/data/)
--skill-evolution        Enable recursive skill evolution (default: True)
--evolution-threshold    Min accuracy to skip evolution (default: 0.4)
--evolution-max-new      Max new skills per evolution step (default: 3)
--evolution-teacher-url  vLLM URL for teacher model (default: same as rollout server)
--evolution-teacher-model Model name for evolution (default: base model)
```
